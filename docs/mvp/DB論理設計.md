
# DB論理設計

## 1. エンティティ（テーブル候補）一覧

MVPとして、以下の5つの主要なエンティティを定義する。

1. **ユーザー（User）**
   - アプリケーションを利用する主体

2. **タグ（Tag）**
   - 「仕事」「勉強」「瞑想」など、活動の種類を分類するマスターデータ

3. **活動セッション（Activity Session）**
   - ある活動を開始してから終了するまでの大きな時間枠を管理するデータ

4. **セッション区間（Session Segment）**
   - 活動セッション内部のFOCUS / BREAK区間を管理するデータ

5. **手動時間記録（Manual Time Entry）**
   - 開始時刻・終了時刻を持たず、合計時間とFOCUS / BREAKの内訳を手動で記録するためのデータ

---

## 2. 各エンティティの項目定義（論理設計）

### ① ユーザー（User）

アプリケーションを利用するユーザーを管理する。

| 論理名 | 必須 | キー | 役割・必要な理由 |
| --- | --- | --- | --- |
| ユーザーID | 必須 | PK | ユーザーを一意に特定するため |
| Google Subject | 必須 | UK | Googleが発行する不変の一意識別子。ログイン時のユーザー照合に使用 |
| メールアドレス | 必須 | - | Googleから取得し、アカウント表示などに使用 |
| 表示名 | 必須 | - | 画面表示に使用 |
| 作成日時 | 必須 | - | システム項目 |
| 更新日時 | 必須 | - | システム項目 |

---

### ② タグ（Tag）

「仕事」「勉強」「瞑想」など、活動の種類を定義する。

ユーザーごとに独自のタグを作成できる。

| 論理名 | 必須 | キー | 役割・必要な理由 |
| --- | --- | --- | --- |
| タグID | 必須 | PK | タグを一意に特定するため |
| ユーザーID | 必須 | FK | タグの所有者を管理するため |
| 表示名 | 必須 | UK (ユーザーID, 表示名) | 同一ユーザー内で同じタグ名を重複させないため |
| カラーキー | 必須 | - | UIでタグを識別する色を保持するため |
| 作成日時 | 必須 | - | システム項目 |
| 更新日時 | 必須 | - | システム項目 |

同一ユーザー内では、同じ表示名のタグを複数作成できない。

---

### ③ 活動セッション（Activity Session）

ユーザーがある活動を開始してから終了するまでの大きな時間枠を管理する。

例:

- 09:00〜12:00：仕事
- 14:00〜16:00：勉強

| 論理名 | 必須 | キー | 役割・必要な理由 |
| --- | --- | --- | --- |
| セッションID | 必須 | PK | 活動セッションを一意に特定するため |
| タグID | 必須 | FK | どの活動に対するセッションかを表すため |
| 活動日 | 必須 | - | どの日の活動として集計するかを決定するため |
| 開始日時 | 必須 | - | セッション開始時刻 |
| 終了日時 | 任意 | - | セッション終了時刻。進行中は未設定 |
| 予定時間（秒） | 任意 | - | セッションの予定時間。通知タイミングに使用 |
| 予定終了日時 | 任意 | - | セッションを何時まで行う予定かを表す。通知タイミングに使用 |
| 作成日時 | 必須 | - | システム項目 |
| 更新日時 | 必須 | - | システム項目 |

#### 制約

- 同一ユーザーについて、時刻を持つ活動セッション同士の時間帯は重複させない。
- 進行中の活動セッションは、同一ユーザーにつき1件までとする。
- 終了日時が設定されている場合、開始日時より後でなければならない。
- 予定時間と予定終了日時は、どちらも任意とする。
- 予定時間と予定終了日時は同時には指定しない。
- 予定時間または予定終了日時は、セッションの実績終了を強制するものではない。

---

### ④ セッション区間（Session Segment）

活動セッション内部のFOCUS / BREAKを管理する。

| 論理名 | 必須 | キー | 役割・必要な理由 |
| --- | --- | --- | --- |
| セッション区間ID | 必須 | PK | セッション区間を一意に特定するため |
| セッションID | 必須 | FK | どの活動セッションに属する区間かを表すため |
| 区間種別 | 必須 | - | FOCUS または BREAK |
| 開始日時 | 必須 | - | 区間の開始時刻 |
| 終了日時 | 任意 | - | 区間の終了時刻。進行中は未設定 |
| 予定時間（秒） | 任意 | - | FOCUS / BREAKの予定時間。通知タイミングに使用 |
| 作成日時 | 必須 | - | システム項目 |
| 更新日時 | 必須 | - | システム項目 |

#### 制約

- 区間種別はFOCUSまたはBREAKのみとする。
- 進行中の活動セッションには、進行中のセッション区間が必ず1件存在する。
- 同一活動セッション内で、セッション区間同士の時間帯は重複させない。
- セッション区間同士の間に空白時間を設けない。
- FOCUSからBREAK、BREAKからFOCUSへ切り替える際は、前の区間の終了日時と次の区間の開始日時を同一とする。
- セッション区間は親となる活動セッションの時間範囲外に存在できない。
- 活動セッション終了時には、進行中のセッション区間も同じ終了日時で終了する。
- 予定時間は区間の実績終了を強制するものではない。

完了した活動セッションでは、以下が成立する。

```text
活動セッション時間
=
FOCUS合計時間
+
BREAK合計時間
````

---

### ⑤ 手動時間記録（Manual Time Entry）

#### 手動入力方式との対応

要件定義で定める手動入力4パターンのうち、
開始日時・終了日時を特定できる以下の3パターンは、
活動セッションおよびセッション区間として記録する。

1. 開始時刻 × 終了時刻
2. 開始時刻 × 合計時間
3. 終了時刻 × 合計時間

これらについては、入力値から開始日時・終了日時を確定し、
ActivitySession と SessionSegment を作成する。

一方、以下のパターンは時間帯を特定できないため、
ManualTimeEntryとして記録する。

4. 時刻なし（合計時間 + FOCUS / BREAK内訳）

開始時刻・終了時刻を持たず、合計時間とFOCUS / BREAKの内訳を手動で記録するためのデータ。

例:

- 活動日：2026-09-06
- タグ：仕事
- 合計時間：2時間
- FOCUS時間：1時間40分
- BREAK時間：20分

時刻を持たないため、活動セッションとは別のデータとして扱う。

| 論理名 | 必須 | キー | 役割・必要な理由 |
| --- | --- | --- | --- |
| 手動時間記録ID | 必須 | PK | 手動時間記録を一意に特定するため |
| タグID | 必須 | FK | どの活動に対する記録かを表すため |
| 活動日 | 必須 | - | どの日の活動として集計するかを表すため |
| 合計時間（秒） | 必須 | - | 活動全体の実績時間 |
| FOCUS時間（秒） | 必須 | - | 合計時間のうちFOCUSとして記録する時間 |
| BREAK時間（秒） | 必須 | - | 合計時間のうちBREAKとして記録する時間 |
| 作成日時 | 必須 | - | システム項目 |
| 更新日時 | 必須 | - | システム項目 |

#### 制約

- 合計時間は1秒以上とする。
- FOCUS時間は0秒以上とする。
- BREAK時間は0秒以上とする。
- FOCUS時間またはBREAK時間のどちらか一方を0秒とすることは可能とする。
- 以下が必ず成立する。

  合計時間 = FOCUS時間 + BREAK時間

- 開始時刻・終了時刻を持たないため、活動セッションとの時間帯重複判定は行わない。

---

## 3. エンティティ間のリレーション

### ユーザー : タグ = 1 : 多

* 1人のユーザーは複数のタグを持つ。
* タグは必ず1人のユーザーに属する。

### タグ : 活動セッション = 1 : 多

* 1つのタグに対して、複数の活動セッションを記録できる。
* 活動セッションは必ず1つのタグに属する。

### 活動セッション : セッション区間 = 1 : 多

* 1つの活動セッションは、1件以上のセッション区間を持つ。
* セッション区間は必ず1つの活動セッションに属する。

### タグ : 手動時間記録 = 1 : 多

* 1つのタグに対して、複数の手動時間記録を登録できる。
* 手動時間記録は必ず1つのタグに属する。

---

## 4. 所有関係

ユーザーと活動セッション・セッション区間・手動時間記録を直接紐づけるユーザーIDは持たせない。

所有関係は以下のリレーションを通じて判定する。

```text
User
  └ Tag
      ├ ActivitySession
      │   └ SessionSegment
      └ ManualTimeEntry
```

活動セッションの所有者:

```text
ActivitySession
→ Tag
→ User
```

セッション区間の所有者:

```text
SessionSegment
→ ActivitySession
→ Tag
→ User
```

手動時間記録の所有者:

```text
ManualTimeEntry
→ Tag
→ User
```

APIではリクエストからユーザーIDを受け取らず、
認証済みユーザーから所有者を判定する。
