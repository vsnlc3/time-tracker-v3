# タイムトラッキングアプリ 要件定義（MVP版）

## 1. コンセプト

リモートワークにおける「仕事」「勉強」「瞑想」などの活動時間を明確に記録・可視化するためのタイムトラッカー。

単純に合計時間を記録するだけでなく、

- 何の活動をしていたか
- その活動をどれくらい継続したか
- その中でどれくらい集中していたか
- どれくらい休憩していたか

を分けて記録できることを目的とする。

たとえば、

- 09:00〜12:00：仕事
  - 09:00〜09:25：FOCUS
  - 09:25〜09:30：BREAK
  - 09:30〜09:58：FOCUS

のように、活動全体の時間と、その内部のFOCUS / BREAKを記録する。

タイマーの設定時間は強制的な終了時刻ではなく、
「次の行動を選択するタイミング」として扱う。

---

## 2. ターゲットユーザー

- 自分自身
- リモートワーク中心で、仕事と休憩の境界が曖昧になりやすい人
- 仕事・勉強・瞑想などに費やした時間を把握したい人
- 活動時間だけでなく、実際の集中時間や休憩時間も確認したい人

---

## 3. 認証・認可方針（MVP）

- Google認証によるログインを必須とする。
- Google認証後はSpring Securityによるサーバーセッションでログイン状態を管理する。
- 未認証ユーザーは本MVPの機能を利用できない。
- 認証済みユーザーは、自身のアカウントに紐づくデータのみ参照・操作できる。
- タグ、活動セッション、セッション区間の取得・作成・更新・削除について、バックエンドで対象データの所有者を確認する。

---

## 4. 時間記録の基本概念

### 4.1 タグ

「何の活動をしているか」を分類するために使用する。

例:

- 仕事
- 勉強
- 瞑想
- 余暇

### 4.2 活動セッション

1つの活動を継続している大きな時間枠。

例:

- 09:00〜12:00：仕事
- 14:00〜16:00：勉強

活動セッションには1つのタグを設定する。

活動セッションは開始後、ユーザーが明示的に終了するまで継続する。

セッションに予定時間または予定終了時刻を設定することもできるが、
予定時間への到達によって自動終了はしない。

同一ユーザーの活動セッション同士は、時間帯を重複させない。
進行中の活動セッションが存在する場合、新しい活動セッションを開始することはできない。

### 4.3 セッション区間

活動セッション内部の状態を表す。

MVPでは以下の2種類のみを扱う。

- FOCUS：作業・集中している時間
- BREAK：休憩している時間

活動セッション中は、常にFOCUSまたはBREAKのいずれかの状態とする。

活動セッション開始時に、初期状態としてFOCUSまたはBREAKを選択できる。

初期選択値はFOCUSとする。

FOCUS / BREAKを細かく切り替えて記録する必要がない場合は、
開始時に選択した状態のまま活動セッション終了まで記録できる。

「FOCUS / BREAK区分なし」という状態は設けない。

### 4.4 活動セッションとセッション区間の関係

- 活動セッション中の全時間は、FOCUSまたはBREAKのいずれかに属する。
- FOCUS / BREAKの区間には空白時間を設けない。
- 同一活動セッション内で、FOCUS / BREAKの時間帯を重複させない。
- FOCUSからBREAK、BREAKからFOCUSへ切り替える際は、現在の区間の終了と次の区間の開始を同一時刻として扱う。
- 完了した活動セッションでは、以下が必ず成立する。

```text
セッション時間 = FOCUS合計時間 + BREAK合計時間
````

例:

```text
09:00 セッション開始 + FOCUS開始
09:28 BREAKへ切り替え
09:35 FOCUSへ切り替え
10:00 セッション終了
```

この場合、以下のように記録される。

```text
活動セッション
09:00 - 10:00

FOCUS
09:00 - 09:28

BREAK
09:28 - 09:35

FOCUS
09:35 - 10:00
```

## 5. MVP（初期リリース）で実装するコア機能

### 5.1 活動セッション

* タグを選択して活動セッションを開始できる。
* セッション開始時に、初期状態としてFOCUSまたはBREAKを選択できる。
* 初期選択値はFOCUSとする。
* セッション開始時に開始時刻を記録する。
* セッション開始と同時に、選択されたFOCUSまたはBREAKの計測を開始する。
* 開始したセッションは、ユーザーが終了するまで継続する。
* 進行中の活動セッションが存在する場合、別の活動セッションを開始できない。
* 新しい活動セッションを登録する際は、既存の活動セッションと時間帯が重複しないことを確認する。
* セッション継続中は、開始時刻からの経過時間をリアルタイムで表示する。
* セッションを終了すると、終了時刻を記録して活動時間を確定する。
* セッション終了時は、進行中のFOCUSまたはBREAKも同時に終了する。
* ページを再読み込み・再訪問しても、進行中のセッションと現在のFOCUS / BREAK状態を復元できる。
* セッションの開始時刻・終了時刻を後から修正できる。
* セッションに予定時間または予定終了時刻を任意で設定できる。
* 予定時間に到達してもセッションは自動終了しない。
* セッションの予定時間に到達した場合、ユーザーへ通知する。

セッション予定時間到達後は、以下の操作を選択できる。

* セッションを継続する。
* セッションの予定時間を延長する。
* セッションを終了する。

### 5.2 FOCUS

* 活動セッション開始時にFOCUSを選択した場合、セッション開始と同時にFOCUSの計測を開始する。
* FOCUSの予定時間を設定できる。
* FOCUSの初期予定時間は25分とする。
* FOCUSは予定時間を設定せずに開始することもできる。
* FOCUSの予定時間に到達したらユーザーへ通知する。
* 予定時間に到達してもFOCUSは自動終了しない。
* ユーザーが操作するまでFOCUSとして継続して計測する。

FOCUS予定時間到達後は、以下の操作を選択できる。

* FOCUSを延長する。
* BREAKへ移行する。
* 活動セッションを終了する。

### 5.3 BREAK

* 活動セッション開始時にBREAKを選択した場合、セッション開始と同時にBREAKの計測を開始する。
* FOCUSからBREAKへ切り替えられる。
* 「BREAKへ移行」を実行した時点で現在のFOCUSを終了し、そのままBREAKを開始する。
* BREAKの予定時間を設定できる。
* BREAKの初期予定時間は5分とする。
* BREAKは予定時間を設定せずに開始することもできる。
* BREAKの予定時間に到達したらユーザーへ通知する。
* 予定時間に到達してもBREAKは自動終了しない。
* ユーザーが操作するまでBREAKとして継続して計測する。

BREAK予定時間到達後は、以下の操作を選択できる。

* BREAKを延長する。
* FOCUSへ移行する。
* 活動セッションを終了する。

### 5.4 FOCUS / BREAK切り替え

通常操作では、FOCUS / BREAKの切り替えをできるだけ少ない操作で行えるようにする。

FOCUS終了時の操作例:

* 「休憩に入る 5分」
* 「FOCUSを延長」
* 「セッション終了」

BREAK終了時の操作例:

* 「集中を再開 25分」
* 「BREAKを延長」
* 「セッション終了」

FOCUSからBREAKへ移行する際に、
「現在のFOCUSを終了する」と「BREAKを開始する」を別々に操作する必要はない。

BREAKからFOCUSへ移行する場合も同様とする。

状態を切り替えた時点で、

1. 現在のセッション区間を終了する。
2. 同じ時刻を開始時刻として次のセッション区間を作成する。
3. 次の区間の計測を開始する。

という処理を行う。

### 5.5 予定時間を設定しない計測

* FOCUS / BREAKは予定時間を指定せずに利用できる。
* 予定時間を設定しない場合は、経過時間を0秒からカウントアップして表示する。
* ユーザーがFOCUS / BREAKを切り替えるか、活動セッションを終了するまで計測を継続する。
* セッション自体についても、予定時間を設定せずに利用できる。

### 5.6 手動入力

実時間を後から登録・修正できるようにする。

以下の4パターンを利用できる。

1. 開始時刻 × 終了時刻
2. 開始時刻 × 合計時間
3. 終了時刻 × 合計時間
4. 時刻なし（合計時間 + FOCUS / BREAK内訳）

1〜3の時刻を特定できる入力では、以下を指定する。

- 活動タグ
- FOCUS / BREAK
- 対象日

入力可能な組み合わせから、不足している開始時刻・終了時刻・合計時間を算出する。

1〜3の入力は、活動セッションとセッション区間として記録する。

4の時刻なし入力では、以下を指定する。

- 活動タグ
- 対象日
- 合計時間
- FOCUS時間
- BREAK時間

時刻なし入力では、以下が必ず成立する。

合計時間 = FOCUS時間 + BREAK時間

開始時刻・終了時刻を持たないため、活動セッションとは別の手動時間記録として扱う。

### 5.7 タグ

* タグを作成できる。
* タグ名を変更できる。
* タグを削除できる。
* 活動セッション開始時にタグを選択できる。

### 5.8 本日のサマリー

* 本日の活動セッションを一覧表示する。
* タグ別の活動合計時間を表示する。
* FOCUSの合計時間を表示する。
* BREAKの合計時間を表示する。
* 各活動セッション内のFOCUS / BREAK履歴を確認できる。
* 時刻なしで登録された手動時間記録も、対象日のタグ別合計・FOCUS合計・BREAK合計に含める。

例:

```text
仕事 09:00〜12:07

セッション時間：3時間7分
FOCUS：2時間32分
BREAK：35分
```

### 5.9 記録の編集・削除

* 活動セッションのタグを変更できる。
* 活動セッションの開始時刻・終了時刻を変更できる。
* 活動セッションを削除できる。
* FOCUS / BREAK区間の種類・開始時刻・終了時刻を変更できる。
* FOCUS / BREAK区間を削除できる。
* 編集後も、活動セッション内の全時間がFOCUSまたはBREAKのいずれかに属する状態を維持する。
* 同一ユーザーの活動セッション同士は、時間帯が重複しないようにする。
* 編集後も、同一活動セッション内でFOCUS / BREAK区間が重複しない状態を維持する。

## 6. タイマーの基本方針

タイマーの予定時間と実際の計測時間は別のものとして扱う。

たとえばFOCUSを25分に設定していても、
25分経過時点で自動終了しない。

25分経過後、3分経ってからBREAKへ移行した場合は、
実際のFOCUS時間は28分として記録する。

予定時間は「区切りを知らせ、次の行動を促すための値」として扱い、
実績時間は実際の開始時刻・終了時刻から算出する。

例:

```text
FOCUS予定時間：25分
実際にBREAKへ切り替えた時刻：開始28分後

予定時間：25分
実績時間：28分
```

予定時間を超過した後も、
ユーザーがFOCUS / BREAKの切り替えまたはセッション終了を行うまで、
現在の状態の実績時間は継続して増加する。

## 7. 基本的な利用イメージ

### 7.1 通常のFOCUS / BREAK利用

```text
09:00
「仕事」を選択
FOCUS 25分でセッション開始

09:25
FOCUS予定時間に到達
通知を表示

09:28
「休憩に入る 5分」を選択

09:28
FOCUS終了
BREAK開始

09:33
BREAK予定時間に到達
通知を表示

09:35
「集中を再開 25分」を選択

09:35
BREAK終了
FOCUS開始

12:00
「セッション終了」

12:00
現在のFOCUS終了
仕事セッション終了
```

### 7.2 BREAKを利用しない場合

FOCUS / BREAKを細かく記録する必要がない場合は、
FOCUSのままセッションを終了できる。

```text
09:00
仕事セッション開始
FOCUS開始

12:00
セッション終了
FOCUS終了
```

結果:

```text
セッション時間：3時間
FOCUS：3時間
BREAK：0分
```

### 7.3 BREAKからセッションを開始する場合

```text
13:00
仕事セッション開始
初期状態としてBREAKを選択

13:05
「集中を再開 25分」を選択

13:05
BREAK終了
FOCUS開始
```

## 8. MVPでは対象外とする機能

以下は将来的な拡張候補とし、MVPでは必須としない。

* 週・月単位の詳細分析
* 高度なグラフ表示
* 通知方法の詳細なカスタマイズ
* FOCUS / BREAK時間のプリセット管理
* 自動FOCUS / BREAK切り替え
* タスク管理機能
* 他ユーザーとの共有
* チーム機能
